# Техническое задание (Шаг 1)

## 1. Проект

**«Финансы»** — личный учёт денег в Telegram Mini App (и как PWA в браузере): расходы и доходы
за месяц, бюджет с планом и фактом по категориям, капитал (счета, активы, кредиты), аналитика.

Основа — ТЗ из ДЗ 3 (`ДЗ опуса/3 - UI-концепции и техническое задание/technical_specification.md`)
и действующее приложение автора. Для ДЗ реализуется **фронтенд**, работающий без сервера,
на вымышленных данных.

### Решение по визуальной части

В ДЗ 3 для интерфейса была выбрана концепция B («яркая»). Автор продукта её попробовал на живом
приложении и отклонил. В продакшене остался iOS-стиль, и дизайн признан замороженным.
Поэтому в этом ДЗ **интерфейс не проектируется заново**. Используется фронтенд действующего
приложения как есть, а новая работа — это слой данных, тесты и проверка адаптивности.
Подробности и история решения — в [development_report.md](../development_report.md).

## 2. Технологический стек

| Слой | Выбор | Почему |
|---|---|---|
| Сборка / dev-сервер | **Vite 5** | Мгновенный HMR, PWA-плагин, тот же, что в проде |
| UI | **React 18** + TypeScript 5 (strict) | Стек действующего приложения |
| Стили / UI-библиотека | **Tailwind CSS 3** + собственные компоненты в iOS-стиле | Готовые UI-киты (MUI и др.) дали бы «чужой» вид; дизайн-система уже есть в проде |
| Роутинг | React Router 7 | Разделы приложения — отдельные URL |
| Данные | TanStack Query 5 + persist в localStorage | Кеш, офлайн-очередь записей, мгновенный старт |
| PWA | vite-plugin-pwa | Установка на экран, офлайн |
| Серверная часть | **Демо-сервер в браузере** (`src/demo/`) | Бэкенда нет: `fetch('/api/…')` перехватывается и обслуживается локально |
| Тесты | Vitest 3 + Testing Library + jsdom | Unit, контракт API, тесты экранов |
| Визуальная проверка | Playwright (headless Chromium) | Скриншоты на 4 ширинах × 2 темах, поиск поломок вёрстки |

## 3. Функциональные требования

Минимум по заданию — 3 функции. Реализовано шесть, ключевые — первые четыре.

| № | Функция | Что делает пользователь | Приёмка (Given-When-Then, кратко) |
|---|---|---|---|
| F1 | **Итог месяца (Главная)** | Видит «Расход за <месяц>», план, остаток / перерасход, капитал, ленту операций | Given есть операции за месяц, When открываю Главную, Then вижу сумму расходов, план и остаток — как в тесте `screens.test.tsx` |
| F2 | **Добавление операции** | Расход: категория → счёт → сумма на клавиатуре → «Сохранить». Также доход, перевод, покупка актива, убыток | Given выбран счёт и введена сумма, When жму «Сохранить», Then операция сохранена, баланс счёта уменьшился. При сбое — «Не удалось сохранить», форма не закрывается |
| F3 | **Бюджет план/факт** | Видит категории со статусом: норма / близко к лимиту / перерасход; меняет лимит | Given «Транспорт» 4 850 из 4 000 ₽, When открываю Бюджет, Then строка первая и помечена 121% |
| F4 | **Капитал** | Видит Net Worth, счета, активы, кредиты; вносит платёж по кредиту | Net Worth = деньги + инвестиции + прочее − кредиты |
| F5 | Аналитика | Периоды, динамика по дням, структура расходов и доходов | Доли категорий в процентах, в сумме ≈ 100% |
| F6 | Настройки | Начало месяца, категории, источники дохода, оформление иконок | Изменения сохраняются |

## 4. Нефункциональные требования

| Требование | Как выполнено |
|---|---|
| **Адаптивность** | Колонка `max-w-md` по центру (как в проде): телефон — на всю ширину, планшет и десктоп — по центру. Проверено автоматически на 320 / 390 / 768 / 1280 px |
| Темы | Светлая и тёмная — по теме Telegram / системы |
| Состояния | Загрузка — скелетоны; ошибка сохранения — диалог с текстом ошибки, ввод не теряется; офлайн — баннер и очередь записей, отправка при появлении сети |
| Безопасность данных | Демо не знает о реальных данных: вымышленные данные хранятся только в localStorage браузера зрителя, запросов наружу нет |
| Производительность | Бандл ~139 КБ gzip, данные из кеша показываются мгновенно |
| Качество | TypeScript strict, `tsc -b` без ошибок, 53 автотеста |

## 5. Демо-режим (вместо сервера)

Поведение демо-сервера повторяет сервер действующего приложения: формы ответов, формат сумм,
пороги статусов бюджета (≤90% — норма, ≤110% — предупреждение, выше — перерасход), тексты
ошибок. Управление — через адресную строку, без изменений интерфейса:

| Параметр | Что делает |
|---|---|
| `?latency=1500` | Задержка ответа сервера, мс — видны скелетоны загрузки |
| `?fail=1` / `?fail=0` | Сервер недоступен / снова доступен |
| `?reset=1` | Вернуть исходные демо-данные |
| DevTools → Network → Offline | Настоящий офлайн: баннер «Без сети», записи копятся в очереди |
